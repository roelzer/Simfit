# Bauplan P4 – Garmin-Daten: normalisieren, Demo, lesen (M2)

**Ziel:** Garmin-Rohformat (`SourceRecord`) streng geprüft in `DailyMetrics`/`Activity` übersetzen (rein), Demo-Quelle im selben Rohformat, Lese-Endpunkte `/daily`, `/activities`, `/activities/{id}`. Schreibt nie in die Datenbank (das macht `store.py`, P5).
**Schwierigkeit:** schwer – fremdes, lückenhaftes Format, Zeitzonen und Zeitumstellung, Blättern ohne Verlust am Tagesrand.
**Risiko-Auslöser:** ja – Daten von außen (Garmin-Werte und -Texte) und neue Lese-Schnittstelle. Sicherheitsprüfer einzeln.
**Abhängig von:** P1a. **Parallel mit:** P5, P6, P8, P11.

Anlegen: `backend/app/garmin/normalize.py` (rein), `backend/app/garmin/demo.py` (rein), Beispieldaten `backend/tests/fixtures/garmin/*.json`, Tests `backend/tests/test_p4_{normalize,demo,read_api}.py`.

`SourceRecord(source, kind, key, payload, failed_parts=())`, `DataSource`, `CancelToken.raise_if_cancelled()`, `OperationAborted`; `DailyMetrics`, `Activity` (Felder ARCHITEKTUR §4); `core.time.to_local(dt_utc, tz) -> datetime`; `core.sports.Sport`, `SPORTS`, `sport_for_type_key(type_key: str | None) -> Sport`; `context.get_ctx(request) -> AppContext`, `context.today_local(ctx, session) -> date`, `context.instance_tz(ctx, session) -> ZoneInfo`; `db.get_session`; `AppError("invalid_input", field=…)`, `AppError("not_found")`; `tests/helpers.make_test_app`, `fixed_clock`.

## Liefert (exakt; P5, P7, P11 bauen dagegen)
- `normalize.py`:
  - `normalize_day(rec: SourceRecord) -> DailyMetrics` – `date = date.fromisoformat(rec.key)`, `source = rec.source`; `updated_at` setzt **nicht** die Normalisierung, sondern `store` (P5). `failed_parts` wird ignoriert.
  - `normalize_activity(rec: SourceRecord, tz: ZoneInfo) -> Activity` – `source = rec.source`, `updated_at` wie oben.
  - `pace_s_per_km(duration_s: float | None, distance_m: float | None) -> float | None`.
  - **Fehlervertrag:** `ValueError` nur, wenn der Datensatz unbrauchbar ist (Tag: `key` kein Datum oder `stats.calendarDate` ≠ `key`; Aktivität: keine `activityId` oder kein lesbares `startTimeGMT`). Einzelne unbrauchbare **Werte** werden `None`, nie Ausnahme. P5 fängt `ValueError` je Datensatz.
- `demo.py`: `class DemoSource` (implementiert `DataSource`, `name = "demo"`), `__init__(self, *, tz: ZoneInfo, today: date, seed: int = 4711)`; `fetch_day(day, cancel) -> SourceRecord`; `fetch_activities(start, end, cancel) -> list[SourceRecord]`; `normalize_day(rec)` / `normalize_activity(rec)` rufen die Funktionen aus `normalize.py` (mit `self.tz`); `save_session()` tut nichts. Dazu `demo_day_payload(day: date, seed: int) -> dict` (rein, deterministisch).
- `read_api.py` (Antwortformen exakt §6): `GET /daily?from&to` → `DailyMetrics[]`; `GET /activities?from&to&sport&limit&before` → `{items: (Activity & {sport})[], next_before: int | null}`; `GET /activities/{id}` → `Activity & {sport}`. Antwort-Schemas `DailyMetricsOut`, `ActivityOut`, `ActivitiesPageOut` liegen in `read_api.py`.

## Feldtabelle (Garmin → Modell; Quelle: `garminconnect/typed.py` 0.3.20 und Prototyp `app/sources/garmin.py`)
| Modellfeld | Teil und Garmin-Feld | Gültig (sonst `None`) |
|---|---|---|
| `steps` | `stats.totalSteps` | ganzzahlig 0–200 000 |
| `distance_m` | `stats.totalDistanceMeters` | 0–500 000 |
| `resting_hr_bpm` | `stats.restingHeartRate` | 20–250, gerundet auf int |
| `avg_hr_bpm` | `stats.averageHeartRate` (nicht in `typed.py`, nur Prototyp – fehlt oft) | 20–250 |
| `stress_avg` | `stats.averageStressLevel` | 0–100 (−1/−2 = kein Wert) |
| `body_battery_high` / `_low` | `stats.bodyBatteryHighestValue` / `bodyBatteryLowestValue` | 0–100 |
| `active_kcal` / `total_kcal` | `stats.activeKilocalories` / `stats.totalKilocalories` | 0–20 000, gerundet auf int |
| `sleep_s` | `sleep.dailySleepDTO.sleepTimeSeconds` | 0–86 400 |
| `sleep_score` | `sleep.dailySleepDTO.sleepScores.overall.value` | 0–100 |
| `hrv_ms` | `hrv.hrvSummary.lastNightAvg` | 1–300 |
| `weight_kg` | `body.totalAverage.weight` (Gramm) ÷ 1000, 1 Nachkommastelle | 20–400 kg |
| Aktivität `source_id` | `str(activityId)` (int oder nicht leerer Text ≤ 64, z. B. Demo `"demo-20261104-1"`) | Pflicht, sonst `ValueError` |
| `type_key` | `activityType.typeKey` **unverändert** (≤ 64 Zeichen, sonst gekürzt) | fehlt → `None` |
| `name` | `activityName`, Steuerzeichen entfernt, ≤ 200 | leer → `None` |
| `start_time_utc` | `startTimeGMT` als UTC | Pflicht, sonst `ValueError` |
| `local_date` | Datumsteil von `startTimeLocal`; fehlt/unlesbar → `to_local(start_time_utc, tz).date()` | – |
| `duration_s` | `duration` (s) | 0 < x ≤ 604 800 |
| `distance_m` | `distance` (m) | 0 < x ≤ 1 000 000 (**0 → `None`**) |
| `avg_hr_bpm` / `max_hr_bpm` | `averageHR` / `maxHR` | 20–250, int |
| `energy_kcal` | `calories` | 0–20 000, int |
| `elevation_gain_m` | `elevationGain` | 0–20 000 |
| `avg_pace_s_per_km` | `pace_s_per_km(duration_s, distance_m)` **nur** wenn `sport_for_type_key(type_key)` in `{"running","walking"}` | 60–3600, 1 Nachkommastelle |

Allgemein für jeden Zahlenwert: nur `int`/`float` (nicht `bool`, nicht Text), `math.isfinite`, im Bereich – sonst `None` (Wert falschen Typs = `None`, keine Ausnahme). Teil `None` oder kein `dict` → alle Felder dieses Teils `None`. Zeitformat: `"YYYY-MM-DD HH:MM:SS"`, auch mit `T` und mit Sekundenbruchteil (`.0`), ohne Zeitzonenangabe = UTC (GMT) bzw. lokal; mit Angabe → umrechnen.

## Demo-Quelle (Regeln)
Gleiches Rohformat wie Garmin (`payload` mit genau `stats, sleep, hrv, body`; Aktivität wie ein Eintrag aus `get_activities_by_date` mit `activityId, activityName, activityType.typeKey, startTimeLocal, startTimeGMT, duration, distance, averageHR, maxHR, calories, elevationGain`). Werte plausibel und deterministisch aus `random.Random(f"{seed}:{day.isoformat()}")`. `body` nur jeden 3. Tag, `hrv` fehlt jeden 7. Tag (Lücken sichtbar). Tage nach `today` → alle Teile `None`. Etwa 4 Aktivitäten je Woche, Startzeit lokal 07:00 oder 18:00 in `tz` → `startTimeGMT` über `zoneinfo` (keine feste Verschiebung); Schlüssel aus `running, cycling, strength_training, walking, lap_swimming, yoga`; `activityId` = `"demo-<YYYYMMDD>-<n>"`. `failed_parts` immer `()`. Liest nie die Uhr, schreibt nie (AE-3, AE-15). Vor jedem Tag bzw. jeder Aktivitätsliste `cancel.raise_if_cancelled()`.

## Lese-Regeln
- `/daily`: Standard `to = today_local(ctx, session)`, `from = to − 29 Tage`; `from > to` → 422 `invalid_input` (`field "from"`), Spanne > 366 Tage → `field "to"`; aufsteigend nach `date`.
- `/activities`: `from`/`to` filtern `local_date` (lokal, AE-7). `sport` muss in `SPORTS` stehen (sonst 422 `field "sport"`); Filter über `SELECT DISTINCT type_key` → je Schlüssel `sport_for_type_key` → `type_key IN (…)` (bei `other` inkl. `type_key IS NULL`). Sortierung `start_time_utc DESC, id DESC`; `before` = `id` einer Aktivität, Fortsetzung strikt nach (`start_time_utc`, `id`) dieser Aktivität (unbekannte `id` → 422 `field "before"`); `limit` 1–100, Standard 30; `limit + 1` laden, `next_before` = `id` des letzten gelieferten Eintrags, wenn es mehr gibt, sonst `null`. `sport` wird beim Lesen berechnet (AE-18), nie gespeichert.
- `/activities/{id}`: unbekannt → 404 `not_found`.
- Nur lesen; keine Garmin-Aufrufe; Ausgabe-Zeitstempel mit `Z`.

## Randfälle
Leere Datenbank → `/daily` `[]`, `/activities` `{items: [], next_before: null}`; `before` zeigt auf die letzte Aktivität → leere Liste; `/daily?from=…` ohne `to` → `to` = heute; Aktivität mit `startTimeLocal` in anderer Zeitzone (Reise) → `local_date` aus `startTimeLocal` (Ortszeit der Aktivität), nicht aus der Instanz-Zeitzone; Tag mit allen vier Teilen `None` → `DailyMetrics` nur mit `date`/`source`.

## Eskalation (BLOCKIERT melden)
`Activity.type_key` oder `Activity.name` sind im Modell (P1a) nicht nullable; ein Feld der Tabelle fehlt im Modell; der Architekturtest „reine Fachlogik“ verlangt eine Ausnahme für `demo.py` oder `normalize.py`; das Blättern lässt sich ohne Schemaänderung (Index) nicht performant bauen.

## Selbstprüfung-Schwerpunkte
`normalize.py`/`demo.py` ohne Uhr, ohne DB, ohne `os` (Architekturtest); kein Schreibzugriff in `read_api.py` (Architekturtest B1); Gegenprobe der Zeitumstellungs-Tests mit fester Verschiebung (müssen rot werden); keine Garmin-Werte im Protokoll.
