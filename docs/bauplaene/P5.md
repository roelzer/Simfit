# Bauplan P5 – Garmin-Abruf: speichern, Sync, Backoff, Sperre (M2)

**Ziel:** Einziger Schreibweg für Garmin-Daten (`store.py`, AE-6), Sync-Lauf mit Vorgangs-Sperre, Abbruch, Backoff und Meldungskatalog (`sync.py`), Auto-Sync (`scheduler.py`), Endpunkte `POST /sync` und `GET /sync/status`.
**Schwierigkeit:** schwer – Nebenläufigkeit (Hintergrund-Thread, Sperre, Abbruch, Generationsnummer) und Datenregeln gegen Datenverlust (B1, B4).
**Risiko-Auslöser:** ja – Daten von außen werden gespeichert (Rangfolge, Zusammenführung), Gleichzeitigkeit mit Verbinden/Löschen. Sicherheitsprüfer einzeln.
**Abhängig von:** P1a. **Parallel mit:** P4, P6, P8, P11 (keine gemeinsamen Dateien; P5 nutzt weder `normalize.py`/`demo.py` noch `token_vault.py` – Tests laufen mit `FakeSource`).

Die Quelle pausiert selbst zwischen ihren Garmin-Aufrufen (Takt AE-8 liegt in P7, nicht im Sync).

## Liefert (exakt)
**`garmin/store.py`** – Schreiben ohne `commit` (der Aufrufer committet je Tag):
- `save_day(session: Session, source: DataSource, rec: SourceRecord, now: datetime) -> Literal["written", "skipped"]`: (1) `rec.source == "demo"` und Tag mit `source="garmin"` vorhanden → `"skipped"`, nichts geändert; (2) erster Garmin-Schreibvorgang (`rec.source == "garmin"` und noch Zeilen mit `source="demo"`) → alle Demo-Zeilen in `DailyMetrics`, `Activity`, `RawRecord` löschen (AE-6 c, gleiche Transaktion); (3) Rohdaten zusammenführen: je Teil (`stats`, `sleep`, `hrv`, `body`) ersetzt ein neuer Teil `None` nie einen gespeicherten Teil (AE-6 e); (4) normalisiert wird der **zusammengeführte** Datensatz (`source.normalize_day(SourceRecord(..., payload=merged))`); (5) gleiche Quelle: `None` überschreibt keinen vorhandenen Messwert (AE-6 a); Garmin über Demo: Zeile vollständig ersetzen; `source`, `updated_at=now` setzt `store`.
- `save_activity(session, source: DataSource, rec: SourceRecord, now: datetime) -> Literal["written", "skipped"]`: eindeutig über (`source`, `source_id`); Rohdaten `kind="activity"` werden ersetzt; Demo-Datensatz bei vorhandenen Garmin-Zeilen → `"skipped"`; gleiche Demo-Löschregel wie oben.
- `demo_allowed(session) -> bool`: `False`, sobald eine Zeile mit `source="garmin"` existiert (Tage oder Aktivitäten) oder `garmin_state.ever_connected` wahr ist. **Einzige Stelle der Rangfolge** – `sync.py` fragt nur hier.
- `has_garmin_rows(session) -> bool`, `has_any_days(session) -> bool` (für P7: Quellenwahl, Erststart).

**`garmin/sync.py`:**
- `SYNC_MAX_DAYS = 90`, `AUTO_SYNC_RANGE_DAYS = 3`.
- `MESSAGES: dict[str, str]` (einziger Meldungskatalog für `sync_run.message`, nie Ausnahmetexte): `"ok": "Abruf abgeschlossen."`, `"ok_incomplete": "Abruf abgeschlossen, {n} Tage unvollständig."` (nur `int` einsetzen), `"error_all_failed": "Garmin hat für keinen Tag Daten geliefert"`, `"error_unavailable": "Garmin ist gerade nicht erreichbar"`, `"error_activities": "Tageswerte geholt, Aktivitäten konnten nicht geladen werden"`, `"error_internal": "Unerwarteter Fehler beim Abruf"`, `"rate_limited": "Garmin hat zu viele Anfragen gemeldet."`, `"auth_required": "Garmin hat die Anmeldung beendet. Bitte neu verbinden."`, `"aborted": "Abruf unterbrochen."`. Fehler-Texte ohne Schlusspunkt (DESIGN 5.2 setzt sie in „…fehlgeschlagen: {message}.“ ein).
- `check_can_start(ctx, session, source: DataSource | None) -> None`: ohne Garmin-Aufruf, Reihenfolge: `source is None` → `garmin_not_connected`; Demo und `not store.demo_allowed` → `demo_blocked`; Garmin und `active_rate_limit` → `AppError("garmin_rate_limited", retry_after=…)`; Garmin und `auth_required` → `garmin_auth_required`.
- `execute_sync(ctx: AppContext, source: DataSource, range_days: int, *, on_started: Callable[[int], None] | None = None) -> SyncRun`: synchron (Tests, Auto-Sync). Ablauf: `check_can_start` → `with ctx.gate.exclusive("sync", preempt=False, wait_s=0) as cancel:` → `SyncRun(status="running", source=source.name, range_days, started_at=clock())` committen → `on_started(run.id)` → `generation = state.token_generation` → Tage von `today_local` rückwärts (**neueste zuerst**), je Tag: `cancel.raise_if_cancelled()` → `source.fetch_day` → `cancel.raise_if_cancelled()` → `store.save_day` → `commit` (eine Transaktion je Tag) → danach einmal `source.fetch_activities(start, end, cancel)` → je Eintrag `store.save_activity` → `commit`.
  Endstatus: alle Tage mit allen vier Teilen in `failed_parts` → `error`/`error_all_failed`; sonst `ok` mit `incomplete_days` = Anzahl Tage mit nicht-leerem `failed_parts` (`ok` bzw. `ok_incomplete`). `garmin_rate_limited` → `register_rate_limit`, Status `rate_limited`, sofort Ende (kein weiterer Aufruf). `garmin_auth_required` → `state.auth_required = True`, Status `auth_required`. `garmin_unavailable` aus `fetch_day` → `error`/`error_unavailable`; aus `fetch_activities` → `error`/`error_activities` (gespeicherte Tage bleiben). `OperationAborted` → `aborted`. Jede andere Ausnahme → `error`/`error_internal`, `logger.exception` (nur Typ und Stacktrace), nicht weiterwerfen. Erfolgreicher Lauf einer Garmin-Quelle (`ok`) → `clear_rate_limit`.
  **Token-Rückschreiben** (im `finally`, noch in der Sperre): `source.save_session()` nur wenn nicht abgebrochen (`cancel.cancelled` falsch), Status nicht `auth_required`, `token_generation` frisch gelesen unverändert und `ctx.settings.token_file.exists()`. Wirft `save_session` → `logger.warning` mit Fehlerkennung, Status bleibt, bei `ok` Meldung unverändert.
  `finished_at`, `status`, `message` in eigener Transaktion schreiben (auch nach Fehlern).
- `start_sync(ctx: AppContext, range_days: int) -> SyncRun`: `source = current_source(ctx)` (**je Lauf neu**); läuft bereits ein Sync (`ctx.gate.current() == "sync"`) → den laufenden `SyncRun` zurückgeben; Sperre durch anderen Vorgang → `operation_busy`; `check_can_start` im aufrufenden Thread (Fehler gehen direkt an die API); dann Daemon-Thread mit `execute_sync(..., on_started=…)`; wartet per `threading.Event` höchstens 10 s, bis `on_started` gerufen wurde oder `execute_sync` vorher mit `AppError` scheiterte (diesen dann weiterwerfen); liefert den angelegten `SyncRun`.
- `latest_run(session) -> SyncRun | None` (nach `started_at`, `id` absteigend).
- `abort_stale_runs(session, now: datetime) -> int`: setzt alle `running` auf `aborted` mit Meldung `aborted` (P7 ruft es beim Start, vor dem Scheduler).

**`garmin/scheduler.py`:**
- `TICK_INTERVAL_S = 300`.
- `auto_sync_tick(ctx: AppContext) -> SyncRun | None`: `None` (ohne Garmin-Aufruf), wenn `auto_sync_hours == 0`, Quelle fehlt oder nicht `"garmin"`, `active_rate_limit`, `auth_required`, Sperre belegt (`gate.current() is not None`) oder letzter Lauf jünger als `auto_sync_hours`; sonst `execute_sync(ctx, source, AUTO_SYNC_RANGE_DAYS)`. `operation_busy` beim Start → Protokoll `info`, `None`.
- `class AutoSyncScheduler`: `__init__(self, ctx: AppContext, *, interval_s: float = TICK_INTERVAL_S)`, `start() -> None` (Daemon-Thread; bei `auto_sync_hours == 0` kein Thread), `stop(timeout_s: float = 5.0) -> None` (Event setzen, Thread beenden). Ausnahmen im Tick werden protokolliert, der Thread läuft weiter.

**`garmin/sync_api.py`:** `POST /sync` Körper `SyncRequest(range_days: int = Field(ge=1, le=90))`, `extra="forbid"` → `SyncRunOut` (200); `GET /sync/status` → `SyncRunOut | None`. `SyncRunOut` = Felder `id, started_at, finished_at, status, message, range_days, source, incomplete_days` (Zeitstempel mit `Z`, entspricht `SyncRun` in P1b `garmin.ts`).

## Randfälle
Leere Aktivitätsliste; `range_days=1`; Tag über Sommerzeitwechsel; Quelle liefert für einen Tag nur `None`-Teile ohne Fehler (= keine Daten, `ok`, kein unvollständiger Tag); `save_session` wirft; Sync-Thread stirbt mit unerwarteter Ausnahme (Lauf muss trotzdem einen Endstatus haben); zwei `POST /sync` gleichzeitig (genau einer startet, der andere erhält denselben Lauf oder `operation_busy`, nie zwei Läufe).

## Eskalation (BLOCKIERT melden)
Die Sperre aus P1a lässt sich nicht aus einem Hintergrund-Thread halten; ein Architekturtest (B1, S9, S14) verlangt eine Ausnahme; die Rangfolge braucht eine Schemaänderung; `start_sync` kann den Start nicht verlässlich melden.

## Selbstprüfung-Schwerpunkte
Kein `session.add/delete` auf `DailyMetrics/Activity/RawRecord` außerhalb `store.py`; kein Ausnahmetext in `message`; jede Ausgangsart des Laufs setzt `finished_at`; Namen exakt (P7 ruft `abort_stale_runs`, `AutoSyncScheduler`, `has_any_days`, `has_garmin_rows`, `execute_sync`).
