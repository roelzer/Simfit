# Bauplan P6 – Garmin-Verbindung, Token-Tresor, Einrichtung (M2)

**Ziel:** Einziger Ort mit `garminconnect` (`connection.py`: Client-Erzeugung, Fehlerübersetzung, Token-Hülle), verschlüsselter Token-Tresor (`token_vault.py`), Einrichtung im Browser mit MFA, Anmeldezähler und Trennen (`setup.py`, `setup_api.py`).
**Schwierigkeit:** schwer – Sicherheit (Passwort, MFA-Zwischenstand, Tokens), Fehlerketten der Bibliothek (B2), Nebenläufigkeit mit dem Sync.
**Risiko-Auslöser:** ja – Anmeldung/Zugangsdaten, Geheimnisse, Daten von außen. Sicherheitsprüfer einzeln.
**Abhängig von:** P1a, Tester-Vorarbeit vor M2 (`backend/tests/fakes/garmin_lib.py`, siehe `VORARBEIT.md`). **Parallel mit:** P4, P5, P8, P11.

## Liefert (exakt)
**`token_vault.py`** (Basis-Modul, importiert nur `app.errors`, `app.settings`, `cryptography.fernet`):
- `secret_key_usable(settings: Settings) -> bool` (Schlüssel gesetzt und gültiger Fernet-Schlüssel).
- `save_tokens(settings, tokens_json: str) -> None`: ohne/ungültiger Schlüssel → `AppError("garmin_secret_missing")`; Ordner `secrets_dir` mit 0700 anlegen; Fernet-verschlüsselt in Temp-Datei im selben Ordner (0600), dann `os.replace` auf `token_file`.
- `load_tokens(settings) -> str | None`: Datei fehlt → `None`; Schlüssel fehlt/ungültig → `garmin_secret_missing`; `InvalidToken` → `garmin_tokens_unreadable`.
- `tokens_readable(settings) -> bool`: wirft nie (fängt nur `AppError` aus `load_tokens`, protokolliert die Kennung).
- `token_file_exists(settings) -> bool`.
- `delete_tokens(settings) -> None`: Datei und Temp-Reste löschen, fehlende Datei ist kein Fehler; `OSError` wird **weitergeworfen** (P13 meldet `delete_incomplete`).

**`garmin/connection.py`** (Modulebene `from garminconnect import Garmin` und die vier Ausnahmeklassen – Tests ersetzen `connection.Garmin` per `monkeypatch` durch `make_fake_garmin(...)`; kein Import von `requests`/`curl_cffi`):
- `translate_error(exc: BaseException, *, phase: Literal["login", "mfa", "sync"]) -> AppError`. Kette = `exc`, dann wiederholt `__cause__` bzw. `__context__` (zyklensicher, höchstens 10 Glieder). Regeln in dieser Reihenfolge: (1) irgendein Glied `GarminConnectTooManyRequestsError`, `response.status_code in (427, 429)` oder `"429"` im Text → `garmin_rate_limited`; (2) Status 403 oder ≥ 500 bzw. eingebautes `ConnectionError`/`TimeoutError` in der Kette → `garmin_unavailable`; (3) `GarminConnectAuthenticationError` in der Kette → `login`: `garmin_credentials_rejected`, `mfa`: `garmin_mfa_invalid`, `sync`: `garmin_auth_required`; (4) alles andere → `garmin_unavailable`. Der Ausnahmetext geht **nie** in `message` (S14); Protokoll nur Klassennamen.
- `class MfaHandle`: undurchsichtig; hält Bibliotheks-Objekt und `client_state`; `__repr__` → `"MfaHandle(<verborgen>)"`; `__reduce__` wirft `TypeError` (nicht serialisierbar); `discard() -> None` setzt beide Verweise auf `None`.
- `@dataclass(frozen=True) class LoginResult: status: Literal["connected", "mfa_required"]; tokens_json: str | None = None; handle: MfaHandle | None = field(default=None, repr=False)`.
- `begin_password_login(email: str, password: str) -> LoginResult`: **einzige** Stelle mit `Garmin(email=..., password=..., return_on_mfa=True)`; `login()` → `("needs_mfa", state)` → `LoginResult("mfa_required", handle=MfaHandle(...))`; `(None, None)` → Tokens über `_dump_tokens` holen, Objekt verwerfen → `LoginResult("connected", tokens_json)`. Fehler → `translate_error(phase="login")`.
- `resume_mfa_login(handle: MfaHandle, code: str) -> str` (Tokens-JSON): `resume_login(client_state, code)`; Fehler → `translate_error(phase="mfa")`; bei Erfolg `handle.discard()`.
- `_dump_tokens(garmin) -> str` (intern): `client.dumps()`; JSON ohne nicht-leeres `di_token` (JWT_WEB-Notweg) → `AppError("garmin_unavailable")`.
- `open_token_client(tokens_json: str) -> TokenClient`: `Garmin()` **ohne Argumente**, `login(tokenstore=tokens_json)` (nie Pfad, nie `GARMINTOKENS`); Fehler → `translate_error(phase="sync")`.
- `class TokenClient` (Hülle, nur von `open_token_client` erzeugt): `get_stats(day: date) -> dict | None`, `get_sleep_data(day: date) -> dict | None`, `get_hrv_data(day: date) -> dict | None`, `get_body_composition(day: date) -> dict | None` (`startdate=enddate=day`), `get_activities_by_date(start: date, end: date) -> list[dict]`, `get_user_timezone() -> str | None` (wirft nie; ungültiger IANA-Name → `None`), `dumps() -> str` (über `_dump_tokens`). Datenaufrufe: `GarminConnectNotFoundError` → `None`; Rückgabe nicht `dict` (bzw. nicht `list` bei Aktivitäten) → `garmin_unavailable`; sonstige Ausnahme → `translate_error(phase="sync")`.

**`garmin/setup.py`:**
- `MFA_TTL = timedelta(minutes=10)`, `LOGIN_ATTEMPTS_PER_HOUR = 3`, `MFA_CODES_PER_LOGIN = 3`.
- `@dataclass(repr=False) class PendingLogin: handle: MfaHandle; created_at: datetime; generation: int; mfa_attempts: int = 0` (`__repr__` ohne Inhalt). Liegt nur in `ctx.pending_login`.
- `login_blocked_until(session, now: datetime) -> datetime | None`: ≥ 3 Versuche in der letzten Stunde → ältester dieser Versuche + 1 h.
- `connection_status(ctx, session) -> dict` → Antwort von `GET /garmin/connection` (§6): `connected = tokens_readable`, `ever_connected`, `auth_required`, `rate_limited_until = active_rate_limit`, `login_blocked_until`, `secret_key_present = secret_key_usable`.
- `connect(ctx, email: str, password: str) -> Literal["connected", "mfa_required"]`: vor jedem Garmin-Aufruf: Schlüssel unbrauchbar → `garmin_secret_missing`; `active_rate_limit` → `garmin_rate_limited` mit `retry_after`; `login_blocked_until` → `garmin_login_limit` mit `retry_after`. Dann `with ctx.gate.exclusive("garmin_connect", preempt=True):` alten `pending_login` verwerfen, `GarminLoginAttempt(attempted_at=now)` **committen vor** dem Aufruf, `begin_password_login`. `mfa_required` → `PendingLogin(generation=state.token_generation)` setzen. `connected` → `_finish(ctx, tokens_json)`. `garmin_rate_limited` → `register_rate_limit` (committen), weiterwerfen.
- `submit_mfa(ctx, code: str) -> Literal["connected"]`: kein Vorgang, abgelaufen (`now − created_at > MFA_TTL`) oder Generation geändert → Vorgang verwerfen, `garmin_mfa_expired`; `active_rate_limit` → `garmin_rate_limited`. Unter `gate.exclusive("garmin_connect", preempt=True)`: `resume_mfa_login`; `garmin_mfa_invalid` → `mfa_attempts += 1`, beim 3. Fehlschlag Vorgang verwerfen, Fehler weiterwerfen; jeder andere Fehler → Vorgang verwerfen, weiterwerfen (429 zusätzlich `register_rate_limit`); Erfolg → `_finish`, Vorgang verwerfen.
- `_finish(ctx, tokens_json)` (intern, in der Sperre): `save_tokens`; `open_token_client(tokens_json).get_user_timezone()` (einziger Token-Login, nur für die Zeitzone; Fehler dabei werden protokolliert, Zeitzone bleibt `None`, Verbindung gilt trotzdem); Zustand: `timezone` (nur gültiger Name, sonst `None`), `bump_generation`, `ever_connected=True`, `auth_required=False`, `clear_rate_limit`; committen. Startet **keinen** Sync (Oberfläche ruft `POST /sync {range_days: 30}`, DESIGN M4).
- `disconnect(ctx) -> None`: `with ctx.gate.exclusive("garmin_disconnect", preempt=True):` `pending_login` verwerfen, `delete_tokens`, `bump_generation`, `auth_required=False`; `ever_connected` und alle Daten bleiben. Ohne Verbindung ebenfalls 204.

**`garmin/setup_api.py`:** `GET /garmin/connection`; `POST /garmin/connection` Körper `ConnectRequest(email: str = Field(min_length=3, max_length=254), password: str = Field(min_length=1, max_length=200))` → `{status}`; `POST /garmin/connection/mfa` Körper `MfaRequest(code: str = Field(pattern=r"^\d{6,8}$"))` → `{status: "connected"}`; `DELETE /garmin/connection` → 204. Alle `extra="forbid"`; Passwort-Feld `SecretStr` oder nie in `repr`/Log.

## Randfälle
Doppelklick auf „Verbinden“ (zweiter Aufruf wartet auf die Sperre und zählt als eigener Versuch); MFA-Code mit Leerzeichen (422); `secrets_dir` fehlt; Temp-Datei bleibt nach Absturz liegen (wird beim nächsten Speichern überschrieben, beim Trennen gelöscht); Zeitzonen-Abruf scheitert mit 429 (Verbindung gilt, `register_rate_limit` **nicht** – die Anmeldung war erfolgreich; nur protokollieren).

## Eskalation (BLOCKIERT melden)
Die Bibliothek verhält sich anders als in `VORARBEIT.md` beschrieben (z. B. `login()` lädt doch ein Profil, `dumps()` liefert andere Felder); ein Architekturtest (A5, B2, S6, S7, S14) verlangt eine Ausnahme; Dateirechte lassen sich im Docker-Volume nicht setzen.
