# Bauplan P11 – Trainingsplan Backend inkl. `/training/today` (M2)

**Ziel:** Pläne und Einheiten anlegen/ändern/löschen, Abgleich „geplant gegen absolviert“ je Woche und „Training heute“ (DESIGN M6).
**Schwierigkeit:** mittel – Abgleich mit klaren Regeln, aber Datumsgrenzen (lokaler Tag, Wochen, Planende) und Zuordnung bei mehreren Einheiten je Tag.
**Risiko-Auslöser:** nein – keine Anmeldung, keine Fremddaten, keine Geheimnisse; neue Endpunkte laufen durch `RequestGuard` (P1a-Test über alle Routen). Prüfung am Meilenstein.
**Abhängig von:** P1a. **Parallel mit:** P4, P5, P6, P8 (keine gemeinsamen Dateien).

## Liefert (exakt)
**`training/matching.py`** (rein, keine Uhr, kein Modell-Import nötig):
- `@dataclass(frozen=True) class MatchSession: id: int; date: date; sport: Sport; sort_order: int; planned_duration_s: int | None`.
- `@dataclass(frozen=True) class MatchActivity: id: int; local_date: date; sport: Sport; start_time_utc: datetime; duration_s: float | None`.
- `@dataclass(frozen=True) class WeekResult: week_no: int; start_date: date; planned_duration_s: int; done_duration_s: int; sessions: list[tuple[int, Literal["done","missed","today","planned"], int | None]]` (Einheit-ID, Status, Aktivitäts-ID); `extra_activity_ids: list[int]`.
- `plan_end(start_date: date, weeks_count: int) -> date` (exklusiv: `start_date + 7 × weeks_count` Tage).
- `compare_plan(start_date: date, weeks_count: int, sessions: list[MatchSession], activities: list[MatchActivity], today: date) -> list[WeekResult]`.
  Regeln: Woche *k* (1-basiert) = `start_date + 7(k−1)` … +6. Je Tag Einheiten nach (`sort_order`, `id`), Aktivitäten des Tages nach (`start_time_utc`, `id`); jede Einheit nimmt die erste noch freie Aktivität **derselben Sportgruppe** (`other` nur mit `other`); jede Aktivität höchstens einmal je Plan. Status: zugeordnet → `done` (auch heute oder in der Zukunft); sonst `date < today` → `missed`, `== today` → `today`, `> today` → `planned`. Nicht zugeordnete Aktivitäten innerhalb des Planzeitraums → `extra_activity_ids` ihrer Woche. `planned_duration_s` = Summe der geplanten Dauern (`None` = 0); `done_duration_s` = Summe `duration_s` **aller** Aktivitäten der Woche (zugeordnet + zusätzlich), auf ganze Sekunden gerundet [ANNAHME, DESIGN „absolviert“].
- `running_plan_id(plans: list[tuple[int, date, int, datetime]], today: date) -> int | None` (ID, Start, Wochen, `created_at`): laufend = `start ≤ today < plan_end`; bei mehreren der zuletzt angelegte (`created_at`, dann `id`).

**`training/service.py`:** `list_plans(session) -> list[TrainingPlan]` (neueste zuerst nach `created_at`, `id`), `get_plan(session, plan_id) -> tuple[TrainingPlan, list[PlannedSession]]` (Einheiten nach `date`, `sort_order`, `id`), `create_plan(session, data, now) -> TrainingPlan`, `update_plan(session, plan_id, data, now) -> TrainingPlan`, `delete_plan(session, plan_id) -> None`, `add_session(session, plan_id, data) -> PlannedSession`, `update_session(session, session_id, data) -> PlannedSession`, `delete_session(session, session_id) -> None`, `comparison(session, plan_id, today: date) -> dict`, `training_today(session, today: date) -> dict`. Unbekannte ID → `AppError("not_found")`. `sort_order` vergibt der Server: neue Einheit = höchster Wert des Tages + 1; beim Datumswechsel ans Ende des neuen Tages.

**`training/api.py`** (Antwortformen exakt wie `training.ts` in `P1b.md`):
- `GET /training/plans` → `TrainingPlan[]`; `POST /training/plans` `PlanInput` → `TrainingPlan` (201); `GET /training/plans/{id}` → `TrainingPlan & {sessions: PlannedSession[]}`; `PUT /training/plans/{id}` `PlanInput` → `TrainingPlan`; `DELETE /training/plans/{id}` → 204 (Einheiten per Löschweitergabe).
- `POST /training/plans/{id}/sessions` `SessionInput` → `PlannedSession` (201); `PUT /training/sessions/{id}` `SessionInput` → `PlannedSession`; `DELETE /training/sessions/{id}` → 204.
- `GET /training/plans/{id}/comparison` → `{weeks: [{week_no, start_date, planned_duration_s, done_duration_s, sessions: [{session, status, activity}], extra_activities}]}`; `activity`/`extra_activities` = Felder von `Activity` (§4, ohne Zusatz).
- `GET /training/today` → `{plan: TrainingPlan | null, sessions: [{session, status, activity}]}` (Einheiten des laufenden Plans mit `date == today`, Status aus `compare_plan`).
- Eingaben (`extra="forbid"`): `PlanInput(name: str 1–200 nach Trimmen, start_date: date – muss Montag sein, weeks_count: int 1–52)`; `SessionInput(date: date, sport: Sport, title: str 1–200 nach Trimmen, planned_duration_s: int | None 1–86400, planned_distance_m: float | None 0 < x ≤ 1 000 000 und endlich, notes: str | None ≤ 500)`.
- Fehler: kein Montag → 422 `invalid_input`, `field="start_date"`; Einheit außerhalb `[start_date, plan_end)` → 422 `field="date"`; `PUT` Plan, bei dem bestehende Einheiten aus dem neuen Zeitraum fallen → 409 `conflict` mit Meldung „Einige Einheiten liegen außerhalb des neuen Zeitraums. Verschiebe oder lösche sie zuerst.“ (keine Einheit wird verändert).
- „heute“ immer `today_local(ctx, session)` (Instanz-Zeitzone, AE-7).
