# Bauplan P14 – Betrieb und Auslieferung (M4)

**Ziel:** Ein Prozess liefert API und statisch exportierte Oberfläche unter `http://127.0.0.1:8000`; Sicherheits-Header mit CSP (Hashes); tägliche Sicherung mit Nachholen, Sicherung vor jeder Migration, Wiederherstellung als Skript; Docker-Compose gehärtet; Startskripte für den Freund (Windows **und** macOS/Linux als Annahme, bis Simon E-2 beantwortet).
**Schwierigkeit:** schwer – Sicherheitsgrenze (Header/CSP, Host-Prüfung im Container), Datensicherung und Wiederherstellung (Datenverlust-Risiko), Startskripte auf zwei Betriebssystemen.
**Risiko-Auslöser:** ja – Serverbetrieb, Geheimnisse (Schlüsseldatei), Sicherung/Wiederherstellung von Gesundheitsdaten, Lieferkette (Images, Lock-Datei). Sicherheitsprüfer einzeln, mit Angriffsversuch Host/Origin per `curl` gegen den Container.
**Abhängig von:** M3 vollständig gemergt (P7, P9, P10, P12, P13), Simons Antwort zu E-2 (siehe Abschnitt „Startskripte“). Läuft allein in M4 (niemand sonst ändert gleichzeitig `main.py`, `settings.py`, `context.py`, `security.py`, `db.py`).

## Liefert (exakt)
**`context.py` (Ergänzung)**
- `@dataclass class BackupStatus: last_ok_at: datetime | None = None; failed_at: datetime | None = None; last_error_code: Literal["disk", "integrity", "busy", "other"] | None = None` (kein Ausnahmetext).

**`backup.py`** (importiert `AppContext`, `BackupStatus` aus `app.context`)
- `daily_backup_path(settings: Settings, day: date) -> Path` → `<backups_dir>/simfit-YYYY-MM-DD.db`.
- `pre_update_backup_path(settings: Settings, now_utc: datetime) -> Path` → `<backups_dir>/simfit-YYYY-MM-DDTHHMMSSZ-vor-update.db`.
- `write_backup(engine: Engine, target: Path) -> None` – **ohne Sperre** (nur für Aufrufer, die die Sperre schon halten): SQLite-Backup-API (`sqlite3.Connection.backup`) in `target.with_suffix(".tmp")`, dort `PRAGMA integrity_check` = `ok`, dann `os.replace` auf `target`; Fehler → Temp-Datei weg, Ausnahme weiterwerfen.
- `create_daily_backup(ctx: AppContext) -> Path` – `with ctx.gate.exclusive("backup", preempt=False, wait_s=60):` `write_backup` nach `daily_backup_path(…, local_today)`, danach `prune_backups`; setzt `ctx.backup_status`.
- `prune_backups(settings: Settings) -> list[Path]` – behält die neuesten `backup_keep_daily` Tages- und `backup_keep_pre_update` Vor-Update-Sicherungen (Sortierung nach Datum im **Namen**, nicht nach mtime); liefert die gelöschten Pfade; andere Dateien im Ordner bleiben.
- `backup_due(settings: Settings, today: date) -> bool` – `True`, wenn `daily_backup_path(today)` fehlt.
- `backup_tick(ctx: AppContext) -> None` – ist eine Sicherung fällig → `create_daily_backup`; `operation_busy` → `last_error_code="busy"` (nächster Versuch beim nächsten Takt), sonst Fehler → `failed_at`, `last_error_code`, Protokoll `log.error` mit Stacktrace ohne Inhalte; nie verschluckt.
- `start_backup_loop(ctx: AppContext, stop: threading.Event, interval_s: float = 3600.0) -> threading.Thread` – Daemon-Thread: sofort ein `backup_tick` (Nachholen nach ausgeschaltetem Rechner), dann alle `interval_s`.
- `list_backups(settings: Settings) -> list[BackupInfo]` mit `BackupInfo(name: str, kind: Literal["daily","pre_update"], created: datetime, size_bytes: int)`, neueste zuerst.
- `restore_backup(settings: Settings, name: str) -> Path` – nur bei **gestoppter** App (eigener Prozess): `name` muss exakt in `list_backups` stehen (kein Pfad, kein `..`), Kopie prüfen (`integrity_check` = `ok`), aktuelle DB nach `<backups_dir>/vor-wiederherstellung-YYYY-MM-DDTHHMMSSZ.db` sichern, `-wal`/`-shm` entfernen, Sicherung als DB einsetzen, erneut `integrity_check`; scheitert ein Schritt → vorherige DB zurück, `RestoreError` mit deutscher Meldung. Läuft die App noch (DB nicht exklusiv sperrbar binnen 2 s) → `RestoreError("Simfit läuft noch. Bitte zuerst ‚Simfit beenden‘.")`.
- `main(argv: list[str] | None = None) -> int` – CLI `python -m app.backup list|restore <name>`; Ausgaben deutsch, Rückgabe 0/1.

**`backup_api.py`**: `router` mit `GET /backup/status` → `{last_ok_at: str|null, failed_at: str|null, failed: bool}` (`failed` = `failed_at` neuer als `last_ok_at`). Beim Start wird `last_ok_at` aus der neuesten Datei in `backups/` gesetzt (Zeitstempel aus dem Namen).

**`web.py`**
- `inline_script_hashes(html: str) -> tuple[str, ...]` – rein: SHA-256 (Base64) über den **exakten** Inhalt jedes `<script>` ohne `src`, in Dokumentreihenfolge, ohne Doppelte; Format `'sha256-…'`.
- `build_csp(script_hashes: Iterable[str]) -> str` → genau: `default-src 'self'; script-src 'self' <hashes>; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`.
- `API_CSP = "default-src 'none'; frame-ancestors 'none'"` (für `/api`-Antworten).
- `class FrontendFiles(StaticFiles)` – `html=True`, setzt je ausgelieferter HTML-Datei die CSP aus einer beim Start berechneten Tabelle `{relativer Pfad: csp}`; unbekannter Pfad → `404.html` mit Status 404 und dessen CSP.
- `mount_frontend(app: FastAPI, frontend_dir: Path | None) -> None` – fehlt der Ordner → nichts einhängen, `log.warning("Oberfläche nicht gefunden …")` (Entwicklung mit `next dev`).

**Sicherheits-Header (`security.py`, auf jede Antwort, auch Fehler und statische Dateien):** `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, `Cross-Origin-Opener-Policy: same-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`; `/api`-Antworten zusätzlich `Content-Security-Policy: API_CSP` und (wie bisher) `Cache-Control: no-store`. **Kein HSTS** (nur `http://127.0.0.1`).
Begründung `style-src 'unsafe-inline'`: Recharts und Radix setzen `style`-Attribute zur Laufzeit; Skripte bleiben streng (nur Hashes, nie `'unsafe-inline'`/`'unsafe-eval'`).

**`db.py`**: `pending_migrations(engine) -> bool` – `True`, wenn die DB Tabellen hat und die Alembic-Revision ≠ `head`; leere/neue DB → `False` (nichts zu sichern).

**Lebenszyklus (`main.py`), Reihenfolge:** (1) `with gate.exclusive("migration"):` falls `pending_migrations` → `write_backup(engine, pre_update_backup_path(…))`; scheitert die Sicherung → `log.critical(START_ABBRUCH_SICHERUNG)` und Start abbrechen (**keine** Migration); sonst `run_migrations`. (2) hängende Läufe/Auto-Sync wie P7. (3) `start_backup_loop`. Beim Herunterfahren `stop.set()`.
`START_ABBRUCH_SICHERUNG = "Simfit startet nicht: Vor dem Update konnte keine Sicherung angelegt werden. Deine Daten sind unverändert. Prüfe, ob genug Speicherplatz frei ist, und starte Simfit dann neu."`

**Frontend:** `system.ts`: `BackupStatus = { last_ok_at: string | null; failed_at: string | null; failed: boolean }`, `getBackupStatus(): Promise<BackupStatus>`. `BackupStatus.tsx`: Text „Letzte Sicherung: heute, 03:12 Uhr“ (Formatierer aus P2, Instanz-Zeitzone); `failed` → `Alert` `warning`: „Die automatische Sicherung hat nicht geklappt. Simfit versucht es in einer Stunde erneut. Wenn das bleibt: Speicherplatz prüfen und Simfit neu starten.“; noch keine Sicherung → „Noch keine Sicherung vorhanden. Simfit sichert einmal am Tag automatisch.“

**Docker (`Dockerfile`):** Stufe 1 `node:<LTS>-slim@sha256:<digest>`: `ENV NEXT_TELEMETRY_DISABLED=1`, `npm ci`, `npm run build` → `out/`. Stufe 2 `python:3.13-slim@sha256:<digest>`: `pip install --no-cache-dir --require-hashes --no-deps -r backend/requirements.lock`, kopiert nur `backend/app`, `backend/migrations`, `backend/alembic.ini`, `out/` → `/app/frontend`; Benutzer `simfit` (UID/GID 10001), `ENV PYTHONDONTWRITEBYTECODE=1 SIMFIT_DATA_DIR=/data SIMFIT_FRONTEND_DIR=/app/frontend`; `CMD ["uvicorn", "app.main:create_app", "--factory", "--host", "0.0.0.0", "--port", "8000", "--workers", "1", "--no-access-log"]`. ## Startskripte (E-2 offen → beide Varianten als [ANNAHME])
Ein Kern je Betriebssystem (`simfit.sh` bzw. `simfit.ps1`) mit den Befehlen `start | stop | update | restore | ensure-key` (`ensure-key` = nur Schlüsseldatei prüfen/anlegen, wird von `start` aufgerufen und von den Tests direkt); die Doppelklick-Dateien rufen nur den Kern mit einem Befehl auf (`.bat`: `powershell -NoProfile -ExecutionPolicy Bypass -File "%~dp0simfit.ps1" start`; `.command`: `cd "$(dirname "$0")" && bash ./simfit.sh start`). Die `.command`/`.sh` sind ausführbar eingecheckt (`git update-index --chmod=+x`). Sobald Simon E-2 beantwortet, entfernt der Projektleiter die nicht benötigte Variante (eigener Commit); bis dahin baut P14 beide.
- **Schlüsseldatei:** Pfad `~/.simfit/simfit.env` (Windows `%USERPROFILE%\.simfit\simfit.env`), außerhalb des Projektordners. Fehlt sie: Ordner anlegen, Image bauen, Schlüssel **im Container** erzeugen (`docker run --rm --network none simfit:local python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`), Datei mit genau `SIMFIT_SECRET_KEY=<schlüssel>` schreiben, Rechte 0600 (Windows: `icacls` nur der aktuelle Benutzer). **Existiert sie (auch leer oder ohne Schlüsselzeile): nie anfassen**; fehlt die Schlüsselzeile → Hinweis, App startet trotzdem (Demo läuft, Garmin-Speichern meldet `garmin_secret_missing`).
- **start:** Docker vorhanden und läuft? (sonst deutscher Hinweis mit Link auf die Anleitung, Ende). Antwortet `http://127.0.0.1:<port>/api/health` schon mit `status: ok` → nur Browser öffnen. Ist der Port anderweitig belegt → Hinweis „Port 8000 ist belegt …“ mit Anleitung, `SIMFIT_PORT=8001` in die Schlüsseldatei zu schreiben (einzige erlaubte Ergänzung, macht der Freund selbst). Sonst `SIMFIT_ENV_FILE` setzen, `docker compose up -d --build`, bis 120 s auf `/api/health` warten, dann Browser öffnen (`open` / `xdg-open` / `Start-Process`). Kommt keine Antwort: die letzten 30 Protokollzeilen (`docker compose logs --tail 30`) und den Hinweis „Simfit ist nicht gestartet …“ zeigen; Fenster bleibt offen (`read`/`Pause`).
- **stop:** `docker compose stop`.
- **update:** fragt Pfad zur neuen ZIP-Datei und die Prüfsumme von Simon, vergleicht SHA-256 (`shasum -a 256` / `Get-FileHash`), bei Abweichung Abbruch ohne Änderung; entpackt in einen **neuen** Ordner neben dem alten (`Simfit-<Datum>`), stoppt den alten Stand (`docker compose stop`), startet den neuen mit `start` (gleicher Compose-Name `simfit`, gleiches Volume, gleiche Schlüsseldatei; die Sicherung vor der Migration macht die App selbst). Der alte Ordner bleibt liegen (Rückweg).
- **restore:** zeigt `python -m app.backup list` (im Einmal-Container mit `-v simfit-data:/data`), fragt die Nummer, fragt „Wirklich zurückspielen? Der heutige Stand wird vorher gesichert. (ja/nein)“, stoppt die App, führt `python -m app.backup restore <name>` im Einmal-Container aus, startet die App wieder und meldet das Ergebnis.
