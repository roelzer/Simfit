- **zusatzbefehle:** `npm --prefix frontend run lint`, `npm --prefix frontend run build`. Nach dem Merge von P1 dazu `"$(command -v python3 || command -v python)" tests/run_all.py --werkzeug bandit`; nach P2 ist `eslint-plugin-security` im Lint enthalten.

**Warum ein eigenes Startskript für die Tests:** Die Test-Schranke zählt nur den **letzten** Treffer des Zählmusters. Mit `pytest && vitest` würde sie verschwundene Backend-Tests nicht bemerken. `tests/run_all.py` startet deshalb pytest über das Python im venv (findet es auf Windows und Linux) und danach `npm --prefix frontend test` (vitest run). Es gibt beide Ausgaben weiter, druckt am Ende `SIMFIT-TESTS: <Summe> passed (pytest a, vitest b)` und endet mit Exit 1, wenn einer der beiden fehlschlägt oder 0 Tests meldet.

**Ausschluss von `.claude/worktrees/` und `.dev-team/`:**
- `pytest.ini` mit `testpaths = backend/tests tests`, `norecursedirs = .claude .dev-team node_modules .venv frontend` und `pythonpath = backend backend/tests`.
- Vitest mit `include: ["src/**/*.test.{ts,tsx}"]` und Wurzel `frontend`.

## Prüf-Schwerpunkt
1. Programm wird mitten im Sync beendet → beim nächsten Start „abgebrochen“, ein neuer Sync ist möglich (P5).
2. Erster echter Sync nach dem Demo-Betrieb → keine Demo-Werte in echten Tagen (P5, P6).
3. Garmin liefert einen Teil nicht oder −1 für „kein Wert“ → dieser Wert bleibt leer, vorhandene Werte bleiben, sichtbare Meldung (P4, P5).
4. Aktivität kurz nach Mitternacht oder in der Nacht der Zeitumstellung → richtiger Tag im Dashboard und im Plan-Abgleich (P4, P7, P11).
5. Kein Internet oder Open Food Facts überlastet → lokale Suche und eigene Lebensmittel bleiben nutzbar, klare Meldung (P9, P10).
